Frontend Optimization Brief

从「混搭赛博朋克 Demo」
到「机构级合规暗池工具」

现有 frony.html 的骨架是对的：首页 → 角色选择 → 交易终端 / 监管终端。 问题在于视觉语言在各页面之间跳跃（紫黑毛玻璃首页 + 绿色扫描雷达 + 纯黑终端）， 以及缺少能让 Cumberland / DWF 量级机构相信这是「真工具」的细节密度与叙事深度。 本文档先给出设计系统 · 信息架构 · 关键时刻方案 · 9 个页面的低保真草图， 等你确认后再做成品。

01

对现有稿的诊断

✓ 保留什么
  • 三视图架构：Landing · 角色选择 · 双终端分视角，这是正确的信息结构。
  • 终端日志作为叙事载体：让 ZK 的「不可见性」变得可见，这是核心张力。
  • 中英双语开关：Colosseum 评审 + 国内机构都覆盖。
  • State machine 驱动的结算流程：PROVING / EXCHANGING / SUBMITTING / SUCCESS 的分段是对的。
✗ 需要重做什么
  • 视觉语言分裂：首页紫黑 3D 网格 vs 内页绿色扫描雷达 vs 纯黑面板，像三个 app。
  • 信息密度不够「机构感」：真正的 OTC 台子屏幕上堆满数字、密文哈希、版本号、CU 计量 —— 现稿太空。
  • 关键技术时刻没被放大：ZK 3 秒生成、双方证明握手、CU = 198,412 —— 这些是卖点，现稿只是平铺日志。
  • 缺少叙事/演示模式：评委 3 分钟内要看懂一次完整结算。
  • 没有品牌符号：「Nexum」只是一个字。
02

统一的视觉系统

保留「landing 更亲和、内页更硬核」的对比，但用一套共享 token 串起来。核心原则： 近黑背景、单色强调、密文即装饰、数字即字体。

保留 sans + mono 混搭。所有密文、地址、CU 数、版本号、哈希、时间戳 必须用 mono —— 这是「机构感」的来源。

背景语言

一套背景，两种强度

Landing 用低频正弦点阵（慢，优雅）；内页用同款点阵但密度 ×2 + 扫描线； 去掉现稿中差异过大的「绿色雷达」。保留一致的近黑底色 #07070A。

组件语言

1px 描边 · 微圆角 · 高对比

所有面板 1px #1c1e27 边、12–14px 圆角、无阴影（无 neon glow）。 机构工具绝不用霓虹发光，只用细描边 + 高对比文字。

数据密度

屏幕上永远有东西在动

侧边永远显示：当前 Solana slot、连接的 Worker 状态、BSGS 表命中率、最近 Settlement 的密文哈希滚动 ticker。 即使静置，也不「安静」。

03

品牌符号概念

Concept A · 双证明 N

字母 N 的两条竖线 = 双方独立 Ledger；虚线对角 = 双方证明之间的数学关系（audit 一致性）。 绿 → 紫 = 本地 ZK → 审计通道。推荐作为主 Logo。

Concept B · Baby Jubjub 曲线

直接用 Twisted Edwards 曲线形状作符号 —— 圈内人一眼认出，圈外人觉得是个优雅的 seal。 适合用作 favicon / 加载动画。

Concept C · 两个 Ledger PDA

两个账本之间一条金线 = 一次结算。下方 v7+1 直接点出「版本号单调递增」这个防重放机制。 更偏工程符号，适合文档封面而不是主 Logo。

建议 采用 Concept A 作主 Logo + wordmark；Concept B 作 favicon / loading；Concept C 用于文档 / PPT 封面。

05

六大关键时刻 · 你选中的全部放大

① 余额：密文 → 本地解密（BSGS 查找表）

页面进入 Trader Terminal 瞬间，余额框显示 ████████████ 占位 → 右侧终端打印 BSGS 建表 0–100% + 实时「步数 / 65,536」→ 建表完成后，余额从密文数字（128 字节 hex 流）以 打字机 + 数字翻滚效果解密为明文「1,250,000.00 USDC」。耗时约 1.5s，全程自动。

② 3 秒 ZK 证明生成

中央证明器面板全屏接管，背景出现 12,778 个小点（= 约束数）逐步点亮，底部横向进度条 + Groth16 四阶段状态（Witness → MSM → Pairing → Serialize）。点亮到 100% 时所有点汇聚成一个 256 字节的发光字符串。

③ 双方证明握手（A ↔ B 对称视觉）

屏幕左右对称分裂：左侧自己的 proof 块，右侧对手方 proof 从远处滑入。中间出现 verify_same_transfer_amount() 的椭圆曲线等式动画 —— 两个 audit_ct.C2 点在 Baby Jubjub 曲线上相减，结果恰好落在 (r_a-r_b)·audit_pk 上 → 亮绿 ✓。

④ 链上密文字段「肉眼可见变化」

结算成功瞬间，底部弹出双行 diff：
ledger_a.balance_ct_lo: 0x2b4f9c…d81a → 0x71fc3e…90b2
ledger_a.version: 7 → 8
字节级高亮哪些 byte 变了。旁边金色 CU 计量表最终定格 198,412 / 400,000。

⑤ TEE Enclave 解密仪式

Regulator 视图点击 Confirm Audit 后进入「仪式动画」：屏幕中央一个由三行 PCR0/1/2 hash 组成的锁环 → AWS KMS Attestation Document 送入 → 锁环逐层旋转对齐 → 释放 DEK → 内层 BSGS_decrypt × 4 解密倒计时 → 明文浮现。整个过程 ~2s，但仪式感拉满。

⑥ AuditLog PDA 强制留痕

审计完成后屏幕分两半：左侧「审计结果 500,000 USDC」，右侧一个 不可关闭的弹窗： 「A permanent AuditLog PDA has been written to Solana · visible to target user forever」+ 链上交易哈希 + 一条飞向 Solana explorer 的动画线。 强调「监管能看但也被看」= 双向透明。

低保真草图 · 9 页

以下每页只画结构与层级，不画精确样式。数字、密文、哈希用占位符表示。 草图风格：近黑底 + 单色线框，与最终稿的「细描边 + 高对比」一致，便于直接升级。

P1

Landing · 机构首页

重做

目标：10 秒内讲清楚「给谁 / 解决什么 / 怎么做到」。去掉现稿的紫黑 3D，用一条 实时结算 ticker 代替，更像真 fintech 产品；三个特性卡从文字卡升级为「带缩略图 + 数字」的证据卡。

P2

角色选择 · Clearance Gate

轻度调整

把现稿的单列居中升级为三列：Trader · Regulator · Developer（新加）。 底部保留三个技术徽章，并把它们从静态 icon 升级为「点击展开 → 显示版本号 / 仓库 / 可信设置参与者数」的胶囊。

P3

Pool Dashboard · 资金池总览（新增）

新增

进入 Trader 后的落地页。左栏 Treasury 明文 TVL（可见，因为存款本来就可见）+ 右栏该用户在 Nexum 内的密文余额矩阵 + 底部 24h 全网结算热力图。

P4

Deposit / Withdraw · 出入金（新增）

新增

一个面板，顶部 Deposit / Withdraw 分段切换。右列持续强调「此步 明文可见，因为此刻你还没有任何交易意图」—— 直接教育用户这不是 bug。

P5

Trader Settlement · 核心结算终端（重做）

核心

三栏：左 = 配置（对手方、金额、角色、审计一致性校验结果预览）· 中 = 证明器舞台（12,778 约束点阵 + 四阶段进度）· 右 = 网络视图（A↔B 握手 + CU 实时计量）。底部常驻：ledger diff viewer（结算前/后密文字段对比）。

P6

Settlement History + Record Detail（新增）

新增

左列表 + 右 drawer。每条记录显示双方审计密文（只有拥有者或被审计时能解密）、双 Groth16 证明（永久存档可独立验证）、结算时间、关联 AuditLog（如被审计过则显示紫色徽章）。

P7

Regulator Audit · 监管审计终端（重做）

重做

三栏叙事：① 选择结算 → ② PCR 锁环仪式（Enclave 身份验证 + KMS 解密授权） → ③ 明文输出 + 强制 AuditLog 留痕弹窗。紫色主题，与 Trader 绿色主题形成分视角差异。

P8

TEE Monitor · Enclave 状态监控（新增）

新增

Dev 或 Regulator 视角可见。目的：建立对 TEE 的信任。公开 PCR 值、KMS 策略绑定条件、最近的 AuditLog 流、确定性构建 Dockerfile 链接 —— 任何人都可以复现相同 PCR。

P9

ZK Circuit View · 电路约束可视化（新增）

新增

Dev 视角的「压轴技术页」。用可视化让评委理解「12,778 个约束到底在约束什么」 —— 六大约束组（旧余额有效、新余额有效、审计密文有效、余额守恒、范围证明、信号共享）呈辐射图，中心是 transfer_lo / transfer_hi 共享信号节点。
